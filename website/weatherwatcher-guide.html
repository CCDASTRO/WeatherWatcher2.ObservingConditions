WeatherWatcher: rain protection and cloud information

Development version 1.2.1, paired with SafetyMonitor 1.3.1 and its preserved AnyCPU compatibility fix. The Arduino monitors the Hydreon RG-11. Windows retrieves NOAA GOES-East cloud-mask data. The IR sky-temperature sensor is no longer used.

Rain controls safety

Rain, lost sensor power, invalid relay contacts or lost Arduino communication produce UNSAFE. Existing automation uses that state to prohibit opening or close an open dome. WeatherWatcher does not directly move the dome.

After valid dry readings resume, the configured dry-out delay must elapse before rain protection permits SAFE. The default is 300 seconds. Existing independent weather limits and selected weather-source health checks still apply.

Setup

  1. Close NINA, WeatherWatcher and other ASCOM clients before updating. Install the matching ObservingConditions and SafetyMonitor drivers. Keep ASCOM Platform 7.1+ and .NET Framework 4.8 installed.
  2. Load the new rain-only Uno sketch and retain the RG-11 relay and isolated power-monitor wiring. Remove the IR module and its four wires.
  3. In WeatherWatcher setup, enable Use Arduino RG-11 rain protection and NOAA cloud information. Enter the Uno COM port and the dry-out delay.
  4. Enter latitude and longitude in decimal degrees. North/east are positive; west is negative. The defaults are a 15 km sampling radius, 600-second NOAA poll, and 1800-second stale timeout. Leaving both coordinates blank allows rain-only operation.
  5. Keep the existing Ambient Weather or Cumulus source configured as desired. Arduino mode takes precedence over Boltwood; disabling Arduino mode restores the existing source behavior.
  6. In NINA select WeatherWatcher2 ObservingConditions and WeatherWatcher SafetyMonitor. Use C:\ProgramData\WeatherWatcher2\weatherdata.txt for the safety file.
  7. Keep ObservingConditions connected to maintain the serial reader and safety output. Close Arduino Serial Monitor so it releases the COM port. SafetyMonitor alone does not start the Arduino reader.

Current wiring and firmware

Retain RG-11 relay COM to Uno GND, NC to D2 and NO to D3. The isolated power-present signal remains on D4. Follow the existing fused 12 V supply, optocoupler and pullup wiring in the hardware guide; never connect 12 V directly to an Uno input. Remove the IR module and its VIN/GND/SDA/SCL wiring; A4/A5 are unused.

Serial remains 9600 baud JSON v1, with a two-second heartbeat, immediate rain-state changes and the existing get#/getd# commands. The new Windows parser ignores legacy IR fields. Upgrade firmware and Windows together: old firmware adds its own five-minute hold, and old Windows code expects IR fields that new firmware no longer sends.

Cloud information

CloudCover is the percentage of good-quality NOAA pixels classified cloudy or probably cloudy inside the sampling radius. This regional satellite estimate updates approximately every ten minutes. It does not measure rain.

Cloudy conditions never make the observatory unsafe. A NOAA or Internet failure retains the last valid cloud observation until it expires; missing or stale cloud data is reported unavailable. Its timestamp is the satellite acquisition time. SkyTemperature is not implemented because the IR sensor is removed.

An independently selected Ambient API source retains its existing failure and safety behavior. NOAA does not change those settings.

Optional Pushover cloud warnings

Open Cloud notifications... in WeatherWatcher setup. Enter your Pushover application token and user/group key, optionally choose a device, and enable notifications. Both keys are masked and protected for your Windows account.

Defaults are a warning at 30% cloud cover, clearing at 20%, and a 30-minute cooldown. You can also enable cloud-data unavailable/recovered notices. Repeated unchanged observations do not send repeated warnings. Automatic warnings require connected ObservingConditions, Arduino/NOAA mode and valid observatory coordinates.

Send test notification sends a real, clearly labeled test using the entered keys. Click OK in both dialogs to save. Normal-priority notifications respect quiet hours. Failed delivery never changes safety or delays rain processing. An Internet outage may also prevent notification delivery.

Get your user key from Pushover and register a WeatherWatcher application for the API token.

Verify before unattended use

Test wet/dry transitions, power/contact faults, USB loss, dry-out recovery and a NOAA outage. Verify that your automation prohibits opening and closes the dome on UNSAFE. Compilation and software tests do not establish that physical wiring or dome closure works.

Enable trace logging for RG-11 transitions, communication failures, SAFE/UNSAFE changes, NOAA retrievals, observation age and cloud percentage. This development build has not been installed or hardware-qualified automatically.
