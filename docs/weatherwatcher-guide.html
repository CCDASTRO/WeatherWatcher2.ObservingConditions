WEATHERWATCHER · OBSERVING CONDITIONS · SAFETY

Your weather station.
Optional local rain and cloud sensing.

WeatherWatcher collects weather data for ASCOM clients. Its companion SafetyMonitor reports whether the combined configured conditions permit observing.

Works with or without RainCloud

ConfigurationBehavior
RainCloud disabled (default)No Uno connection is attempted. Existing AmbientWeather, Cumulus and Boltwood configuration remains in use.
RainCloud enabled and validUno rain and cloud readings supplement existing weather limits and replace the Boltwood rain/cloud input.
RainCloud enabled but missing or faultedConnection may fail, or the combined result becomes unsafe. Missing data is never treated as dry or clear.

To operate without the optional sensor, disconnect WeatherWatcher clients, uncheck Use Uno RainCloud in setup, save, and reconnect. Restore the desired Boltwood selection if applicable.

Two sensors, one Arduino

  • Hydreon RG-11: optical rain detection with relay output. Reports detected rain activity; it does not prove a surface is completely dry.
  • GY-906 / MLX90614: measures sky-facing infrared and internal sensor temperatures to estimate local cloudiness.
  • Arduino Uno R3: sends measurements and health flags to Windows over USB every two seconds.

The design reads both rain relay contacts and includes a sensor-power monitor. These detect some wiring and supply faults but cannot detect every sensor failure. The infrared module requires a suitable outdoor enclosure and an unobstructed infrared view.

How the ASCOM connection works

Sensors → Uno USB → WeatherWatcher → ObservingConditions and SafetyMonitor → NINA

A shared reader owns the Uno COM port. WeatherWatcher exposes sky temperature and calibrated cloud estimates while retaining the weather station's other measurements. Rain detection contributes to safety without inventing a rainfall rate or replacing air temperature with the IR chip's temperature.

WeatherWatcher publishes a timestamped combined safety result. The updated SafetyMonitor rejects expired or future-dated RainCloud results. Keep ObservingConditions connected in NINA; SafetyMonitor does not start the USB reader itself.

Installation and NINA setup

Development build: one Inno Setup package contains WeatherWatcher ObservingConditions 1.1.0 and SafetyMonitor 1.3.1. The installer has been compiled, but installation and physical sensor commissioning are not yet validated. The suite is available as a development prerelease in the combined WeatherWatcher repository.

  1. Close NINA, WeatherWatcher and other clients using these drivers. Install both through the combined installer. Windows 10+, ASCOM Platform 7.1+ and .NET Framework 4.8 are required.
  2. Existing ASCOM profile settings are retained. RainCloud is disabled by default on first use.
  3. For sensor operation, load and test the Uno sketch, then open WeatherWatcher setup and select Use Uno RainCloud instead of Boltwood rain/cloud input.
  4. Enter the Uno COM port and maximum acceptable cloud estimate. Keep the normal AmbientWeather or Cumulus source configured.
  5. In NINA select WeatherWatcher2 for Observing Conditions and WeatherWatcher SafetyMonitor for Safety Monitor. Point SafetyMonitor to the combined output at C:\ProgramData\WeatherWatcher2\weatherdata.txt.
  6. Connect Observing Conditions to start reading the Uno. Close Arduino Serial Monitor so it releases the port.

Use the matching updated SafetyMonitor with RainCloud enabled; older versions do not enforce the new timestamp expiry. A previous standalone SafetyMonitor uninstall entry may remain after upgrading: use the combined package for future maintenance, because uninstalling the old entry can remove the shared safety driver.

Calibration and recovery

Cloud estimates initially remain uncalibrated and cannot produce a safe result. Collect readings under known clear and overcast skies at the final mount, then set the sketch's calibration endpoints. The result is an estimate within the sensor's field of view, not a forecast or a precise whole-sky cloud percentage.

Rain and faults interrupt recovery. The Uno requires five minutes without an asserted rain output, and Windows requires a separate five-minute clear recovery. Missing sensor data times out after ten seconds. The safety file also expires ten seconds after its last update; total reaction time includes these stages and NINA's polling interval.

126 offline checks passed, including existing weather-source tests, rain/cloud faults and safety-record expiry. Bench-test power loss, sensor unplugging, rain response and recovery before relying on the new input. Continue using independent weather protection during commissioning.
